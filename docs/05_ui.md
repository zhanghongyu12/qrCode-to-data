# UI 设计

> 状态：草稿
> 最后更新：2026-08-14
> 维护者：Designer

> 说明：本项目为「CLI 工具 + 手机移动网页」双界面形态，故 UI 设计分两大部分。**第一部分**为终端 CLI 交互（MVP/Phase 1，对应 PRD F-01~F-06），**第二部分**为手机移动网页 PWA（Phase 2 手机离线中转，对应 PRD F-08）。二者复用同一套「光学收发 + 喷泉码 + 校验」核心能力，因此本设计假设存在统一的传输清单（manifest）与块帧格式，详见文末「§6 接口假设」。

| 界面 | 编号 | 形态 | 阶段 | 目标用户 | 路由/入口 |
|------|------|------|------|---------|-----------|
| 发送（CLI） | C-01 | 终端字符 / 独立窗口 | Phase 1 (P0) | 开发者/运维/安全敏感 | `qrcode send` |

## 1. 设计风格

### 1.1 整体风格

- **终端（CLI）**：极简、高信息密度、以「可扫描性」为第一优先。二维码渲染区与文字信息区严格分离，二维码区域内不放任何彩色/渐变，确保摄像头识别率。
- **移动网页**：深色科技风（深底高对比，适配扫码场景与屏幕播放二维码），以「扫码取景 + 大二维码播放」两个核心动作为中心，操作少而直接。

## 3. 界面设计

### C-01: 发送（CLI）

**功能说明：** 接收文件路径或文本，经分块 + 喷泉码编码后逐块生成二维码，在终端（字符渲染）或独立窗口播放。

**usage（假设，供 Architect 对齐）：**

```
用法: qrcode send <载荷> [flags]

  <载荷>                 文件路径；或配合 -t 直接发送文本
  -t, --text string      直接发送文本内容（与位置参数二选一）
      --stdin            从标准输入读取文本
      --fps int          二维码播放帧率（帧/秒），默认 6（范围 1~30）
      --version int      二维码版本/尺寸，默认自动适配
      --ecc string       纠错级别 L|M|Q|H，默认 M
      --redundancy float 喷泉码冗余度，默认 0.3（即 30% 冗余）
      --window           在独立窗口渲染二维码（默认终端字符渲染）
      --no-progress      关闭进度显示
  -h, --help             usage 帮助
```

**布局描述（终端字符渲染）：**

```
═══════════════════════════════════════════════════
  [发送] 文件: config.tar.gz  大小: 2.3 MB
  载荷ID: ab12cd  块: 230  冗余: 30%  校验: SHA-256
═══════════════════════════════════════════════════

      ██████████████  ██  ██████████████
      ██        ██  ██    ██        ██
      ██ ██████ ██  ████  ██ ██████ ██
      ██ ██████ ██  ██    ██ ██████ ██
      ██ ██████ ██  ██ ██ ██ ██████ ██
      ██        ██    ██  ██        ██
      ██████████████  ██  ██████████████
      ...（二维码动画序列，逐帧刷新，此区域禁止彩色）...

  ┌─────────────────────────────────────────────┐
  │ 进度: ████████████░░░░░░░░ 48%  (112/230 块) │
  │ 速率: 6.0 fps    预计剩余: 18s                │
  │ 提示: 按 Ctrl+C 停止                          │
  └─────────────────────────────────────────────┘
```

**交互说明：**

1. 用户执行 `qrcode send <载荷>`；工具解析载荷类型（文件 / 文本）。
2. 启动即显示「载荷ID / 总块数 / 冗余度 / 校验算法」摘要头（便于接收端对账）。
3. 进入播放态：按 `--fps` 帧率循环播放二维码序列（喷泉码块，乱序播放，无需等待）。
4. 实时刷新进度条：已播块数 / 总块数、百分比、速率（fps 或 块/s）、预计剩余时间。
5. 短文本（F-05）走「单张/少量二维码」路径：不启动动画，仅静态显示 1~N 张二维码，并提示「可被第三方扫码 App 直接读取」。
6. 播放中断（Ctrl+C）：立即停止并释放资源，输出「已停止，已播 112/230 块」。
7. 载荷过大时：在播放前提示预估时长，并建议走同网加速（Phase 2，F-07）。

**状态说明：**

| 场景 | 表现 |
|------|------|
| 正常播放中 | 二维码动画 + 进度条实时刷新 |
| 短文本 | 静态 1~N 张二维码，无进度条，提示「扫码即得」 |
| 文件不存在/无权限 | `✘ 错误: 文件不存在或无读取权限: <路径>` + 退出码非 0 |
| 参数缺失/错误 | 打印 usage，`✘ 错误: 必须指定文件路径或 --text` |
| 载荷过大 | `⚠ 警告: 预计传输时长约 4 分钟，建议使用同网加速`，继续播放 |
| 终端不支持 UTF-8/彩色 | 降级为 ASCII `##` 渲染（见 §3.3） |
| 终端过小放不下二维码 | 提示增大终端窗口，或改用 `--window` |
| 用户 Ctrl+C | 立即停止并释放资源 |

**组件列表：**

| 组件 | 类型 | 说明 |
|------|------|------|
| 载荷摘要头 | 文本块 | 载荷ID/总块数/冗余/校验 |
| 二维码播放区 | 渲染区 | 字符或窗口渲染，禁止彩色 |
| 进度条 | 进度组件 | 已播/总块数、百分比、fps、剩余时间 |
| 提示/错误行 | 文本行 | 中文可操作提示 |

### C-02: 接收（CLI）

**功能说明：** 调用摄像头连续扫描 QR 流，实时解码编码块，收够阈值后经喷泉码还原，完成完整性校验并落盘。

**usage（假设，供 Architect 对齐）：**

```
用法: qrcode receive [flags]

  -o, --output string   输出目录，默认当前目录 (.)
      --camera int      摄像头设备号，默认 0
      --version int     二维码版本/尺寸，默认自动适配
      --ecc string      纠错级别 L|M|Q|H，默认 M
      --blocks int      期望块数（用于进度计算，可选）
      --size string     期望总大小，如 2.3MB（可选）
      --timeout int     连续无新块超时秒数，默认 30
      --no-verify       跳过完整性校验（不推荐）
      --no-progress     关闭进度显示
  -h, --help            usage 帮助
```

**布局描述：**

```
═══════════════════════════════════════════════════
  [接收] 正在扫描二维码流…
  摄像头: /dev/video0    期望块数: 230（自动识别）
═══════════════════════════════════════════════════

  ┌─────────────────────────────────────────────┐
  │ 进度: ████████████████░░░░ 76%  (收 175/230) │
  │ 唯一块: 175   去重: 12   速率: 8.2 块/s       │
  │ 校验: 等待还原完成…                            │
  └─────────────────────────────────────────────┘
```

**交互说明：**

1. 用户执行 `qrcode receive`，工具打开摄像头并进入持续扫描态。
2. 每解到一个编码块：若为新块则计数 +1，若为已收块则计入「去重」并忽略（F-03）。
3. 实时刷新进度：唯一块数 / 期望块数、百分比、去重数、速率。
4. 收够喷泉码还原阈值后自动还原，进入校验态，输出哈希比对结果。
5. 校验通过：输出文件路径、大小、SHA-256，退出码 0。
6. 校验失败：丢弃已还原数据（或标记为损坏），提示重传，退出码非 0。
7. 连续 `--timeout` 秒无新块：提示「长时间未收到新块，请调整距离/角度」，允许 Ctrl+C 终止。

**状态说明：**

| 场景 | 表现 |
|------|------|
| 正常接收 | 进度条实时刷新（唯一块/期望、去重、速率） |
| 还原 + 校验通过 | `✔ 校验通过  SHA-256: a1b2c3…  → 已写入 ./output/config.tar.gz (2.3 MB)` |
| 校验失败 | `✘ 校验失败  已丢弃损坏数据，请重传`，退出码非 0 |
| 无摄像头/权限拒绝 | `✘ 错误: 摄像头不可用或无访问权限: <设备>`，退出 |
| 解码持续失败/无法对准 | `⚠ 提示: 无法稳定解码，请调整距离与角度` |
| 中途断流 | 喷泉码补足后继续；不足则 `✘ 错误: 已收块不足以还原，请重试` |
| 目标路径不可写 | `✘ 错误: 输出目录不可写: <路径>`，退出 |
| 无新块超时 | 提示调整对准 + 可 Ctrl+C |

**组件列表：**

| 组件 | 类型 | 说明 |
|------|------|------|
| 接收摘要头 | 文本块 | 摄像头设备/期望块数 |
| 进度条 | 进度组件 | 唯一块/期望、去重数、速率 |
| 校验结果 | 结果组件 | 通过/失败 + 哈希 + 落盘路径 |
| 提示/错误行 | 文本行 | 中文可操作提示 |

### 3.3 终端字符二维码渲染（无 GUI 降级方案）

本方案是 F-02「无 GUI 场景（纯终端字符渲染二维码）」的落地设计，也是 CLI 默认渲染模式。

**渲染规则：**

1. **半块字符**：用 UTF-8 半块字符 `▀`（上半）`▄`（下半）`█`（全块）与空格 ` `，每个字符承载 2 个垂直模块，二维码纵向密度翻倍，显著提升摄像头可识别性。
2. **强制黑白**：二维码区域只用「亮模块 + 暗模块」两种颜色，禁用 ANSI 彩色。深色终端用「亮块=白色前景」，浅色终端用「暗块=黑色前景」，保持高对比。
3. **静区（quiet zone）**：上下左右各保留 ≥4 模块的空白，终端中以空格补齐，防止定位框缺失。
4. **帧刷新**：用 ANSI 光标复位（`\x1b[H` 或 `\x1b[<n>A`）回到起始位置覆盖上一帧，禁止滚动累积。
5. **尺寸自适应**：读取终端行列数，选择「含静区」能完整放下的最大二维码版本；放不下则提示用户增大窗口或改用 `--window`。
6. **ASCII 降级**：终端不支持 UTF-8（如 `LANG=C`、无 UTF-8 locale）时，退化为每个模块用 2×2 的 `##` 与 `  ` 渲染，并提示「已降级为 ASCII 渲染，建议放大终端」。

**独立窗口（`--window`）模式：** 弹出一个无边框/大尺寸窗口，二维码居中、四周留足静区、纯黑白，窗口下方可选显示帧序号；有 GUI 环境时优先推荐此模式。

### P-01: 接收（扫码）— 移动网页

**功能说明：** 手机摄像头对准电脑屏幕的 QR 流，实时扫描解码、喷泉码还原、校验，成功后暂存到本地（IndexedDB）。

**布局描述（ASCII 线框图）：**

```
┌──────────────────────────────┐
│  ← 接收（扫码）                 │  ← 顶部栏：标题 + 返回
├──────────────────────────────┤
│                              │
│    ┌────────────────────┐    │
│    │   摄像头取景框      │    │  ← 全屏取景 + 四角对焦框
│    │   (video 预览)     │    │
│    │   [扫码引导线]     │    │
│    │   已收 175/230 块   │    │  ← 悬浮进度胶囊
│    └────────────────────┘    │
│                              │
│  ┌────────────────────────┐  │
│  │ 进度条 ████████░░░ 76%  │  │  ← 底部信息面板
│  │ 去重 12 · 速率 8.2块/s  │  │
│  │ [停止接收]              │  │
│  └────────────────────────┘  │
│  ①接收   ②暂存   ③发送        │  ← 底部 tab bar
└──────────────────────────────┘
```

**交互说明：**

1. 进入页面请求摄像头权限（`getUserMedia`），成功即显示取景框并开始扫描。
2. 自动识别 QR 流 → 解码编码块 → 去重计数 → 进度实时刷新。
3. 收够阈值后自动还原并校验，成功后弹出「已保存到暂存」，自动跳转至暂存列表（P-02）。
4. 「停止接收」按钮可中途终止，已收块保留在内存态（未完成不写库）。
5. 扫码引导线仅在未收到首个有效块前显示，收到后切换为进度胶囊。

**状态说明：**

| 组件 | Loading | Empty | Error | Edge Case |
|------|---------|-------|-------|-----------|
| 取景框 | 请求摄像头权限中（转圈） | 未开始扫描，显示引导线 | 权限拒绝：提示「无法访问摄像头，请在浏览器设置中允许」 | 解码失败：提示调整距离/角度 |
| 进度面板 | 等待首块 | 无 | — | 长时间无新块：提示对准 |
| 保存结果 | 还原/校验中 | — | 校验失败：提示重扫 | **存储空间不足：阻止接收并提示清理（F-08）** |
| 页面整体 | 首次打开加载资源 | — | 浏览器不支持摄像头/存储：明确提示 | 页面刷新：已暂存数据仍在，未完成接收丢弃 |

**组件列表：**

| 组件 | 类型 | 说明 |
|------|------|------|
| 顶部栏 | 导航 | 标题 + 返回 |
| 取景框 | 摄像头组件 | video 预览 + 四角对焦 + 引导线 |
| 进度胶囊 | 悬浮组件 | 已收/期望块、去重、速率 |
| 底部信息面板 | 面板 | 进度条 + 停止按钮 |
| 底部 tab bar | 导航 | 接收/暂存/发送 三入口 |

### P-02: 暂存列表（管理）— 移动网页

**功能说明：** 展示手机本地暂存的数据条目，支持查看详情、删除（二次确认）、空间占用提示；为默认首页。

**布局描述：**


### P-03: 发送（重放）— 移动网页

**功能说明：** 将选中的暂存数据重新编码为 QR 流，在手机屏幕上全屏播放，供另一台电脑的 `qrcode receive` 扫描。

**布局描述：**

```
┌──────────────────────────────┐
│  ← 发送  config.tar.gz        │  ← 顶部栏
├──────────────────────────────┤
│                              │
│        ██████████████        │
│        ██        ██          │
│        ██ ██████ ██          │
│        ██ ██████ ██          │  ← 全屏二维码播放区
│        ██        ██          │     （纯黑白、屏幕常亮）
│        ██████████████        │
│        ...（QR 流循环播放）... │
│                              │
│  进度: 48% · 帧 112/230 · 6fps │  ← 底部信息
│  [暂停]  [停止]  亮度: ▓▓▓░    │  ← 控制条 + 亮度
│  ①接收   ②暂存   ③发送        │
└──────────────────────────────┘
```

**交互说明：**

1. 从 IndexedDB 读取暂存数据 → 复用与 CLI 相同编码逻辑重新生成 QR 流。
2. 全屏播放区强制黑白、自动调至最高亮度、申请屏幕常亮（Wake Lock API，若不支持则降级为尽量延迟锁屏）。
3. 控制条提供「暂停/继续」「停止」；亮度滑块手动调节。
4. 进度实时刷新：帧序号/总块、百分比、fps。
5. 播放结束后自动循环（喷泉码乱序，接收端收够即可还原）；用户可随时停止。

**状态说明：**

| 组件 | Loading | Empty | Error | Edge Case |
|------|---------|-------|-------|-----------|
| 播放区 | 读数据/编码中（转圈） | 数据不存在：提示并返回列表 | 编码失败：提示并返回 | 屏幕自动锁屏：请求 Wake Lock 失败时提示 |
| 控制条 | — | — | — | 数据过大：提示预计播放时长 |
| 进度 | 等待首帧 | — | — | — |

**组件列表：**

| 组件 | 类型 | 说明 |
|------|------|------|
| 顶部栏 | 导航 | 标题 + 返回 |
| 二维码播放区 | 渲染区 | 全屏纯黑白 QR 流 |
| 控制条 | 控制 | 暂停/继续、停止、亮度滑块 |
| 进度条 | 进度组件 | 帧序/总块、百分比、fps |
| 底部 tab bar | 导航 | 接收/暂存/发送 三入口 |

## 5. 响应式设计

移动网页以手机竖屏为主，采用单列布局；平板/桌面浏览器按宽度做有限增强。

| 断点 | 宽度 | 布局 |
|------|------|------|
| 移动端 | < 768px（主目标） | 单列；取景/播放区占满首屏；底部 tab bar 固定 |
| 平板端 | 768-1024px | 内容区限宽 640px 居中；取景/播放区保持 1:1 |
| 桌面端 | > 1024px | 内容区限宽 480px 居中，模拟手机视口；tab bar 仍固定于内容区底部 |

终端（CLI）无响应式概念，但二维码字符渲染会根据终端行列数自适应选择最大可容纳的二维码版本（见 §3.3 规则 5）。

## 6. 本设计假设以下接口存在（供 Architect 对齐）

> 以下为 UI 设计所依赖的契约假设，与 Architect 并行期间未见 `04_api.md` 详细设计。若最终接口不同，请在本节或 `docs/07_decisions.md` 回写对齐。

1. **CLI 命令契约**：二进制名假设为 `qrcode`，含 `send` / `receive` 两个子命令，参数见 §3.1/§3.2 的 usage 块（`--fps/--version/--ecc/--redundancy/--window/--camera/--output/--blocks/--size/--timeout/--no-verify/--no-progress` 等）。
2. **传输清单（manifest）**：假设存在统一结构，承载一次传输的元信息，被编码进每帧二维码（或首帧），供两端及手机端互相识别。UI 需要其中字段：载荷ID、载荷类型（text/file）、文件名/文本摘要、总块数、块大小、喷泉码参数与冗余度、原始字节数、校验算法与校验值（SHA-256/CRC32）。
3. **块帧格式**：假设每帧二维码承载「manifest 片段 + 编码块序号 + 编码块数据」，接收端据此去重与进度计数。
4. **可复用的光学收发核心**：假设编码/解码、喷泉码、分块、校验的核心逻辑可同时被 CLI 与移动网页复用（移动端为 JS/WASM 实现），且能向上层抛出统一进度事件（已收/总块、去重数、速率、校验结果）。UI 只消费这些事件，不关心底层实现。
5. **移动网页数据持久化**：假设暂存数据以 IndexedDB 存储，空间配额通过 `navigator.storage.estimate()` 获取。
6. **PWA 资源清单**：假设存在 `manifest.json`（应用名/图标/主题色）与 Service Worker 缓存策略（预缓存 shell，离线可用）。
