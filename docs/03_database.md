# 本地存储设计

> 状态：草稿
> 最后更新：2026-08-14
> 维护者：Architect

> 说明：本项目为 CLI 工具 + 手机移动网页，**无传统数据库（无服务端、无 SQL、无多租户）**。本文档描述「哪些数据需持久化」与「本地文件系统/浏览器存储约定」。凡传统数据库概念均明确标注「不适用」并说明理由，不硬套 SQL 表结构。

---

## 1. 数据库选型

| 项目 | 选择 |
|------|------|
| 数据库类型 | **不适用** —— 无服务端、无关系型/NoSQL 数据库 |
| 版本 | 不适用 |
| 字符集 / 排序规则 | 不适用 |

**理由**：本工具是单机单用户 CLI，数据要么「立即落盘为用户指定的文件」，要么「短生命周期暂存在内存」，要么「Phase 2 手机中转暂存于浏览器 IndexedDB」。不存在需要数据库解决的并发、事务、查询、多实例一致性问题。引入任何数据库（SQLite 等）都是过度设计，违背「零配置」定位。

---

## 2. 持久化需求清单

| 数据 | 是否持久化 | 存储位置 | 生命周期 |
|------|-----------|---------|---------|
| 接收端还原的文件/文本 | 是（用户主动输出） | 用户指定路径（`--output`） | 永久，用户自行管理 |
| 接收中的临时文件（`.part`） | 是（传输期） | 输出目录下 `.part` 临时文件 | 校验通过后 rename 为最终名；失败/中断则清理或标记损坏 |
| 手机中转暂存数据（Phase 2） | 是 | 浏览器 IndexedDB | 手动清除前保留；断电/刷新不丢失 |
| 发送端待传载荷 | 否 | 内存流式读取 | 发送即读即弃 |
| 传输会话元数据（transfer_id、哈希、FEC 参数） | 否 | 内存 | 单次会话结束即释放 |
| 用户配置（默认参数） | 可选（Phase 2 起） | 桌面端配置文件（见 §4） | 用户删除前保留 |

---

## 3. 桌面端本地文件系统约定

### 3.1 输出文件约定

- 接收端默认输出到当前目录；`receive --output <dir|file>` 可指定目录或完整文件名。
- 文件名来源：元数据帧携带的原始文件名；文本载荷默认 `stdin.txt` 或用户指定。
- **原子落盘**：还原数据先写 `<name>.part`，整体 SHA-256 校验通过后 `rename` 为 `<name>`；校验失败则丢弃 `.part` 并提示重传，绝不静默写出损坏文件。
- 已存在同名文件：默认拒绝覆盖并提示，`--overwrite` 显式允许覆盖。

### 3.2 临时文件与清理

- 临时文件统一 `<name>.part`，与最终文件同目录（保证同文件系统 rename 原子性）。
- 正常完成 / 失败退出 / Ctrl+C 中断时，均清理遗留 `.part` 文件。
- 不写系统临时目录以外的隐藏文件。

### 3.3 配置文件约定（可选，Phase 2 起）

- 目的：记忆用户常用的默认参数（默认 QR version、fps、redundancy 等），MVP 优先走命令行参数，配置仅为可选项。
- 格式：TOML（简单、Go 标准库可解析，避免引入 YAML 复杂依赖）。
- 路径（跨平台约定）：
  - Linux/macOS：`~/.config/qrcd/config.toml`（遵循 XDG）
  - Windows：`%APPDATA%\qrcd\config.toml`
- 优先级：命令行参数 > 配置文件 > 内置默认值。
- 不存储任何凭据、token、用户数据。

## 4. 手机端存储方案（Phase 2：IndexedDB）

手机中转的「暂存」需要本地持久化且断电/刷新不丢失（PRD F-08），浏览器环境下 IndexedDB 是唯一合适选择（localStorage 容量小且同步阻塞、不存 Blob）。

### 4.1 IndexedDB 结构

- 数据库名：`qrcd`
- object store：`transfers`（keyPath = `id`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string（主键） | 传输会话 ID（复用帧协议 transfer_id） |
| `name` | string | 原始文件名 / 文本标识 |
| `size` | number | 载荷总字节数 |
| `mimeType` | string | 内容类型（`text/plain` 或 `application/octet-stream`） |
| `sha256` | string | 载荷 SHA-256（十六进制，还原校验用） |
| `blocks` | Array<Blob> | 还原后的分块数据（或合并后单个 Blob） |
| `receivedAt` | number | 接收时间戳（毫秒） |

> 说明：`blocks` 是否分块存储由前端实现取舍——小载荷存单 Blob，大载荷分块存便于流式读。schema 仅约定字段语义，具体实现不强制。

### 4.2 容量与清理

- 容量：受浏览器配额限制，接收前先估算并检查（`navigator.storage.estimate()`），不足则提示并阻止接收（PRD F-08 异常处理）。
- 清理：提供「手动删除」入口，删除即 `indexedDB.delete` 彻底清除，不自动上传。
- 持久化：页面刷新不丢失；清缓存/卸载浏览器可能清除，界面需明确提示「暂存数据仅存本机」。

### 4.3 安全

- 暂存数据仅存本机浏览器存储，不经过任何服务器。
- P2 可选：暂存时用 XChaCha20 加密（用户口令），防止手机浏览器被其他页面读取。MVP 不做，标记待后续决策。

---

## 5. 数据迁移策略

- **不适用**：无数据库 schema 迁移。跨版本兼容由「帧协议 version 字段」与「配置项向后兼容默认值」承担，不做数据迁移。
- 配置文件演进：新增键必须有默认值，删除键忽略未知项（向前兼容）。

---

## 6. 数据安全

### 6.1 备份策略

- 不适用：工具不承担用户数据的备份职责；还原结果由用户自行备份。

### 6.2 敏感数据

- 桌面端不持久化敏感数据；token 仅存内存、单次使用。
- 手机端暂存数据可被浏览器本地读取，涉密场景建议启用 P2 加密或传输后立即清除。

---

## 7. 性能优化

- 桌面端：`.part` 顺序写 + rename，无随机 IO；载荷流式分块，不整体载入大文件到内存。
- 手机端：大载荷分块写 IndexedDB，避免单事务过大导致浏览器卡顿。
- 分库分表 / 读写分离 / 缓存：均不适用（无数据库、单用户、数据短生命周期）。
