# 产品想法

> 状态：已确认
> 最后更新：2026-08-14
> 维护者：PM

## 一句话描述

一个通过二维码在设备间传输数据/文件的命令行工具：默认用纯二维码光学传输（无需网络/蓝牙/USB），两端同网时自动切换 WiFi 直传加速；并支持用手机作为离线中转站，在隔离的两台电脑间摆渡数据。

## 背景与动机

- 两台设备间传文件/文本，通常依赖网络、蓝牙、U 盘或云盘；但很多场景下这些手段不可用或不方便：
  - **空气隔离机器（air-gapped）**：出于安全不允许联网，导出数据只能靠"屏幕 + 相机"。
  - **服务器 / 嵌入式设备**：无 GUI、无外设，临时传个配置文件很麻烦。
  - **跨网段 / 访客网络**：无法直连，但屏幕和摄像头是通用的。
  - **离线摆渡（sneakernet）**：两台机器既不能联网、又不在同一处时，手机可充当"数据搬运工"——先扫码收下数据暂存，走到另一台机器前再扫码发出去。
- 二维码是唯一"零配置、零依赖"的通用传输媒介：只要有屏幕就能发，只要有摄像头就能收。
- 现有开源方案各自为政——纯光学的 txqr/RaptorQR、扫码走 WiFi 的 qrcp——**缺少"纯光学为主、同网自动加速、手机可中转"的一体化 CLI**。

## 目标用户

| 用户类型 | 特征 | 核心需求 | 使用场景 |
|---------|------|---------|---------|
| 开发者 / 运维 | 常用终端，熟悉命令行 | 在终端快速传文件/文本，不折腾 | 服务器间传配置、隔离机导出日志 |
| 安全敏感场景 | 设备不允许联网 | 数据不出物理边界 | 空气隔离环境的数据导出/导入 |
| 离线摆渡场景 | 两台隔离电脑 + 一台手机 | 数据在隔离机器间安全摆渡 | 涉密机导出 → 手机中转 → 另一台涉密机导入 |
| 普通用户（次之） | 电脑 + 手机 | 免装 App 传文件 | 电脑↔手机传照片/文档 |

## 核心价值

1. **零网络依赖**：纯光学传输不需要任何网络，数据只经过"屏幕→相机"，天然物理隔离。
2. **零配置**：一条命令即可收发，无需配对、无需安装接收端。
3. **兼顾速度**：同网时自动切换 WiFi 直传，避免纯光学的吞吐瓶颈。
4. **时间解耦**：手机中转让收发双方无需同时在场，数据可暂存、随时再发。
5. **安全**：数据不经过任何第三方服务器/云端。

## 初步功能想法

- 发送端：把文件/文本编码成二维码动画序列，在终端/屏幕上播放（MVP）
- 接收端：调用摄像头扫描二维码流，实时解码还原（MVP）
- 喷泉码纠错：抗漏帧、抗顺序错乱，无需 ACK/重传（MVP）
- 文本直传：短文本用单张/少量二维码，扫码即得（MVP）
- 传输进度与完整性校验（CRC / 哈希）（MVP）
- 同网检测 + WiFi 加速：两端同网时自动走局域网直传，二维码只做握手（P1）
- 手机中转：移动网页端实现"收 → 暂存 → 发"，手机作离线数据摆渡站（P1）

## 竞品/参考

| 项目 | 语言 | 方案 | 我们的差异 |
|------|------|------|-----------|
| divan/txqr | Go | 动画二维码 + LT 码 | 仅纯光学，无同网加速/中转；可作为编码参考 |
| infrost/RaptorQR | TS | 动画二维码 + RaptorQ + 双层 FEC | 是 Web 应用非 CLI；吞吐极致 |
| claudiodangelis/qrcp | Go | 扫码握手 + WiFi | 仅 WiFi 路径，无纯光学能力 |
| coolwill/qr-tunnel | Java | 二维码传文件 | 单一路径 |
| leonjza/qrxfer | Python | 空气隔离二维码导出 | 单向导出，场景窄 |

差异化：**纯光学 + 同网加速 + 手机中转的一体化 CLI**，三条能力按场景组合，现无直接竞品。

## 技术初步想法

- 语言候选：Go（单二进制 CLI、二维码库成熟、txqr 即 Go）或 Python（原型快）；倾向 Go
- 纠错码：RaptorQ（RFC 6330）或 LT 码（gofountain）
- 二维码生成/解析：go-qrcode / ZXing / fast_qr
- 扫描：系统摄像头 + ZXing
- WiFi 直传：HTTP 临时服务 + 二维码承载连接信息（参考 qrcp）
- 手机端：移动网页（PWA，浏览器打开即用、可离线），复用浏览器摄像头扫码 + 屏幕播放

## 可行性初步评估

### 市场

小众但真实（开发者/运维工具），有成熟开源生态可参考；差异化是"纯光学 + 同网加速 + 手机中转"三合一，现无直接竞品。

### 技术

核心算法（喷泉码、二维码编解码）均有成熟开源实现，主要工作量在工程集成与扫描鲁棒性；吞吐优化是难点但非阻塞。手机中转在"收发两端能力对称"的前提下几乎不增加核心复杂度，仅新增"手机网页 + 本地暂存"。

### 资源

个人项目，时间投入可控；纯光学点对点可先跑通 MVP，再依次迭代 WiFi 加速与手机中转。
