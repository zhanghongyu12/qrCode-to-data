# AI 专家讨论规则

 # AI 专家讨论规则
 
 > 本规则用于两个 Expert 的**结构化辩论**。
 > 如果是两个角色之间的**日常协作沟通**（如 Architect ↔ Designer 交叉确认），请使用 `.ai/rules/coordination_rules.md`。
 > 一个 session 要么是辩论，要么是协作，由 context.md 的"类型"字段区分。
 
## 路径与 session_id 约定

- 每次讨论在 `.session/{session_id}/` 目录下进行，session_id 格式为 `YYYYMMDD` + 两位序号（如 `2026071301` 表示 2026 年 7 月 13 日的第 1 轮讨论）。
- 编排者启动讨论前必须：
  1. 创建 `.session/{session_id}/` 目录
  2. 在 `.session/{session_id}/context.md` 中填写讨论背景，并写明 `输出目录: .session/{session_id}/`
- Expert 不直接写 `discussion.md`，而是将各自独立输出写入输出目录下的 `expert_a.md` 和 `expert_b.md`。
- 编排方负责收集两个 Expert 的独立输出后，合并写入 `discussion.md`，再进入 Phase 2 交叉挑战。
- context.md 缺少输出目录字段时，Expert 必须报错停止，不得自行猜测路径。

---

## 目标

两个 AI 作为独立专家，对同一个问题进行深入分析。

目标不是互相说服，而是：

- 发现不同视角
- 暴露隐藏风险
- 比较不同方案
- 形成最佳决策

---

# 基本原则

## 1. 平等原则

AI-A 和 AI-B 地位相同。

不存在：

- 老师
- 学生
- 执行者
- 审核者

双方都是专家。

---

# 2. 独立思考

每个 AI 第一次分析时：

禁止读取对方观点。

目的：

避免思维污染。

必须先形成自己的判断。

---

# 3. 观点碰撞

第二阶段：

双方读取对方观点。

必须：

- 指出认可部分
- 指出不同意见
- 给出理由
- 提供替代方案

---

# 4. 禁止无意义争论

禁止：

"我同意"

"你说得对"

必须说明：

为什么。

---

# 5. 所有讨论记录写入

由编排方合并两个 Expert 的独立输出后写入 `.session/{session_id}/discussion.md`

格式：

## Round X

### AI-A

内容

### AI-B

内容

---

# 6. 最终必须产生

`.session/{session_id}/synthesis.md`

包含：

- 共识
- 分歧
- 最优方案
- 未解决风险

---

# 讨论阶段

## Phase 1 独立分析

两个 AI 分别提出方案，输出到 `.session/{session_id}/expert_a.md` 和 `.session/{session_id}/expert_b.md`（由 Expert 直接写自己的独立文件）。
编排方收集两个 Expert 的独立输出后，合并写入 `.session/{session_id}/discussion.md`。
Phase 1 期间禁止任何 Expert 读取对方输出。

## Phase 2 交叉挑战

双方读取 `.session/{session_id}/discussion.md` 中对方的观点，互相分析。

## Phase 3 深度优化

结合双方观点。

## Phase 4 总结

生成最终方案，写入 `.session/{session_id}/synthesis.md`。

# 自动辩论模式（Auto-Debate Mode）

> 以下章节定义"自动辩论模式"。
> 该模式下，两个 agentic CLI（Claude Code、Codex、Qoder 等）在各自窗口中通过共享文件 + sleep 轮询自主辩论，
> 人工只在关键节点点头，不传话、不算数字、不写文件结构。
> 一个 session 要么是"人工传话模式"（即上文 Phase 1-4），要么是"自动辩论模式"，由 context.md 的"类型"字段区分：
> - 类型: 辩论        → 人工传话模式（上文规则）
> - 类型: 自动辩论    → 自动辩论模式（下文规则）

## A. 设计原则

| 原则 | 含义 |
|------|------|
| **文件是唯一真相** | 轮数、截止时间、状态等所有状态存在文件中，模型每轮读取，不依赖自身记忆 |
| **人工只点头** | 全程只动嘴（粘话术、回"同意/不同意"），不手敲数字、不改文件结构、不算轮数 |
| **人工在关键节点做决策** | 人工负责启动、同意延期、通知"继续讨论"等关键决策，agent 负责执行。原文"人工只点头"是理想定位，实际操作中人工需做多项操作 |
| **截止时间 / MAX_ROUNDS 未经人工同意不得修改** | agent 可请求，不可自主改写；授权后可写预定值 |
| **终止信号存在于模型之外** | 轮数、墙钟、STOP 文件，均独立于模型记忆 |
| **暂停可续** | `已停止` 状态保留全部上下文，随时恢复，不丢讨论历史 |

## B. 文件结构

```
.session/{session_id}/
  context.md          ← 状态、轮数预算、截止时间、审批字段
  board.md            ← 消息板（append-only）
  current_round.txt   ← 当前已完成的轮数（纯数字，单行）
  max_rounds.txt      ← MAX_ROUNDS 封顶值（纯数字，单行）
  turn.txt            ← 当前该谁发言（单字符 A 或 B）
  STOP                ← 人工 kill 开关，出现即强制退出
  expert_a.md         ← Phase 1 独立输出（Expert A）
  expert_b.md         ← Phase 1 独立输出（Expert B）
  discussion.md       ← 仅人工传话模式使用，自动辩论模式不适用
  synthesis.md        ← 最终产出
```

**current_round.txt**：纯数字单行，无注释。当前已完成的轮数。agent 每轮发言后 +1 写回。
**max_rounds.txt**：纯数字单行，无注释。MAX_ROUNDS 封顶值。人工授权后 agent 改写。
**turn.txt**：单字符（A 或 B），无注释。当前该谁发言。agent 写完 board.md 后更新 turn.txt。对方 sleep 醒来先读 turn.txt，轮到自己才读 board.md。

**自动辩论模式文件角色**：
- board.md → 自动模式下的对话记录 + 轮询信号（替代 discussion.md）
- discussion.md → 仅人工传话模式使用，自动模式下列为"不适用"
- expert_a/b.md → Phase 1 独立输出，Phase 2 起只读
- context.md → 状态、轮数预算、截止时间、审批结果字段
- turn.txt → 轻量轮次信号，避免每次读全文 board.md

**board.md 格式规范**（自动辩论模式）：
```
## Round N

### Expert A
（内容）

### Expert B
（内容）
```
每轮以 `## Round N` 开头，各方发言以 `### Expert A/B` 标注。

**turn.txt 与 board.md 写入顺序**：先写 board.md，确认已刷新到磁盘，再更新 turn.txt。两个都确认后才 sleep。

## C. context.md 模板（自动辩论模式）

参见 `.ai/rules/ExpertDebate/context_auto_template.md`。
启动自动辩论 session 时，编排者（人工或第一个加入的 agent）按该模板填写。

## D. 终止保险（全部跨 OS、纯规则类）

四条独立保险，**谁先触发谁先生效**，互不干扰。

| 保险 | 触发条件 | 触发动作 | 硬上限 |
|------|---------|---------|--------|
| **轮数封顶** | `round.txt` 当前值 ≥ MAX_ROUNDS | 进 synthesis（诚实标注） | 初始 ≤ 20，延期后封顶 32 |
| **延期次数** | `已延期次数` ≥ 2 | 不再接受延期，强制 synthesis | 2 次 |
| **墙钟截止** | `now + 缓冲 ≥ 截止时间` | 状态改 `已停止`，发停止消息，退出 | 单次延长 ≤ 60 分钟，总延长 ≤ 2 次 |
| **人工 kill** | `STOP` 文件存在 | 立即退出，不写任何新内容 | 人工手动建 |

**轮数封顶 / 延期次数触发时，synthesis 必须诚实：**

- **已达成一致**：必须能在 board.md 中找到双方明确认可的原文证据。找不到证据的，一律归入"仍存在争议"。
- **仍存在争议**：列出每个未决分歧点，附双方各自立场，标注"未收敛"。禁止把分歧写成共识。
- **未触及**：因轮数耗尽根本没讨论到的问题。

### 提前结束机制

当双方在 board.md 中明确确认无剩余分歧后，可跳过剩余轮数直接进入 Phase 4：

1. **提议**：任一 agent 在 board.md 追加"提议提前进入 Phase 4（无剩余分歧）"
2. **确认**：对方看到后，若同意则在 board.md 追加"确认提前进入 Phase 4"；若认为有遗漏，则指出遗漏点，继续讨论
3. **进入**：双方确认后，任一 agent 直接开始写 synthesis.md

两步确认流程，防止一方单方面宣布结束。

## E. 轮数预算与延期

### E.1 预估

第一个加入的 agent（通常是 Expert A）读完 context.md 后，预估本次讨论需要的轮数，写入 context.md 的 `计划轮数` 和 round.txt 的 `MAX_ROUNDS`。

**硬上限：初始预估不得超过 20 轮。** 超过视为违规，必须降到 20 以内才能写。
预估不是承诺，是起点——第一次延期应是常态而非例外。

"一轮"的定义：双方各发一次算 1 轮。

### E.2 计数

每轮发言后，发言者把 round.txt 第一行（当前轮数）+1 写回。只有发言者本人能写，避免双写冲突。

### E.3 临近上限触发延期

当 **剩余轮数 ≤ 2**（即 `MAX_ROUNDS - 当前轮数 ≤ 2`）**且** 模型自评"分歧点还剩 ≥ 2 个"时：

- agent 直接执行延期：`max_rounds.txt` 值 +N（N ≤ 6），`已延期次数` +1
- board.md 追加 `类型: 延期通知` 消息（非请求），说明：剩余分歧点、已延长轮数、理由
- context.md `审批结果` 字段设为 `待否决`，人工有异议通过 STOP 或回复"停止"否决
- 人工未否决则继续讨论（自动延期生效）

**不触发的条件**：剩余 ≤ 2 轮但只剩 1 个小分歧时，让模型自己把最后一点吵完，不强行触发延期。

### E.4 人工否决

延期自动生效后，人工如有异议：
- 回复 `停止` 或建 STOP 文件 → 状态改 `已停止`，不写 synthesis，board.md 保留，随时可恢复
- 不回复 → 延期继续生效，agent 继续讨论

### E.5 硬约束

- 初始预估 ≤ 20 轮
- 单次延期 ≤ 6 轮
- 总延期 ≤ 2 次
- 第三次触发延期请求时，agent 必须明确告知"已达延期上限，无法继续"，进 synthesis 收尾

## F. 墙钟机制

### F.1 填截止时间

启动时填，ISO 8601 带时区格式，硬上限 120 分钟。缺时区视为无效，agent 必须报错停止，不得自行猜测时区。

### F.2 每轮取真实时间

agent 每轮 sleep 前获取一次当前真实时间（系统时钟，非模型记忆），用于墙钟判断。取时间失败时本轮跳过墙钟判断，照常 sleep，下轮重试。

**获取方式不限**——可用 shell 命令、可用工具调用、可用 MCP、可自行编写脚本，由 agent 根据所处环境自行选择。

**约束**：输出必须能解析为合法 ISO 8601 带时区格式，否则视为取时间失败。

### F.3 超时判断

`now + 墙钟缓冲 ≥ 截止时间` 时触发。缓冲 30 秒，防多 agent 时钟不同步造成竞态。

### F.4 超时动作

1. board.md 追加 `类型: 墙钟超时` 消息，明确写："因为时间到了，讨论停止。" 列出当前未决分歧点
2. context.md 状态改 `已停止`，填 `停止时间: <now>`
3. 退出，不 sleep 轮询

## G. 恢复机制

### G.1 人工通知

恢复由人工分别通知两个窗口，各粘一句"继续讨论 session {session_id}"。
agent 不负责拉对方回来——人工对"谁在跑、谁没跑"有完全控制。

### G.2 agent 收到"继续讨论"后的行为

agent 重新启动，读到 `已停止` 状态后：

- 写新的截止时间（`截止时间` = now + 人工指定延长量），更新 context.md
- 状态改回 `进行中`
- board.md 追加 `类型: 恢复` 消息
- 继续轮询讨论

人工主动说"继续"本身就是授权，不需要额外审批流程。

### G.3 铁律

**未经人工同意，agent 不得修改 `截止时间` 字段。** 人工通知"继续讨论"视为授权延长，agent 可写新截止时间。

### G.4 恢复前的必检

恢复前 agent 必须检查 context.md 的 `截止时间`：
- 若 `截止时间` 未被人工更新过（仍为旧值）**且** `已延长次数` 未增加，视为无效，报错停止，要求人工更新
- 若 `截止时间` 已被更新为新值（> now），视为有效，继续轮询

**执行顺序**：先检查截止时间是否有效（G.4），再写新截止时间恢复（G.2）。

**注意**：原 G.5 中"停止时间 <= now 则无效"的判定有逻辑缺陷——墙钟超时后停止时间必然 <= now，但这不代表恢复无效。正确判定是检查截止时间是否已被更新，而非停止时间。

## H. 双向停止（已停止状态的传播）

第一个 agent 触发 `已停止`（墙钟超时或延期被拒）时，写消息、改状态、退出。

第二个 agent 下一轮 sleep 前读到 `已停止` 状态，**自动停止退出**：
- 不需要额外通知
- 不自己发停止消息（避免重复）
- 直接退出，等待人工通知

## I. Sleep 轮询循环

每个 agent 的自主循环（伪代码）：

```
读 context.md 状态
  ├─ 已停止 / 已结束 → 退出
  ├─ STOP 文件存在 → 立即退出，不写任何内容
  ├─ 待否决 → sleep 90秒，重读（人工未否决则继续）
  └─ 进行中 →
      获取当前真实时间（方式不限，结果须 ISO 8601 带时区）
      ├─ 取时间失败 → 跳过墙钟判断，照常 sleep
      ├─ now + 缓冲 ≥ 截止时间 → 执行超时动作，退出
      读 current_round.txt + max_rounds.txt
      ├─ 当前值 ≥ MAX_ROUNDS → 进 synthesis（诚实标注）
      ├─ MAX_ROUNDS - 当前值 ≤ 2 且分歧 ≥ 2 → 自动延期，board.md 发通知
      读 turn.txt
      ├─ 不是自己 → sleep 90秒，重读
      └─ 是自己 → 读 board.md 末条消息
      ├─ 是对方的 → 回复，写回 board.md，round +1
      └─ 是自己的 → sleep 90秒，重读
```

**Sleep 间隔**：正常轮询 90 秒（降低空转）。turn.txt 为轻量信号，先读 turn.txt 判断是否轮到自己，轮到才读 board.md 全文。

## J. 初始触发（防死锁）

两个 agent 都 sleep 等对方会死锁。约定：

- **Expert A** 启动时不 sleep，直接写第一轮（Phase 1 独立分析，写 expert_a.md）
- **Expert B** 启动后看到 A 有消息才进入轮询

Phase 1 的独立分析阶段不受 sleep 轮询约束，Expert A/B 各自独立写 expert_a.md / expert_b.md。
sleep 轮询从 Phase 2 交叉挑战开始。

## K. 人工操作清单（全程）

| 时机 | 人工做的事 |
|------|------------|
| 启动 | 开两个窗口，各粘一次"加入 session"话术 |
| 延期通知出现 | 如有异议回复`停止`或建 STOP 文件，无异议则不管 |
| 墙钟停止后想续 | 分别通知两个窗口："继续讨论 session {id}" |
| 想强制停 | 建 `STOP` 文件（可选，很少用） |
| 结束 | 什么都不做，模型自己关 |

**全程不手敲数字、不改文件结构、不算轮数。**

## M. 与人工传话模式的关系

| 维度 | 人工传话模式（类型: 辩论） | 自动辩论模式（类型: 自动辩论） |
|------|--------------------------|------------------------------|
| 驱动 | 人工复制粘贴通知话术 | agent 自主 sleep 轮询 |
| 工具要求 | 任何 AI 工具 | 须为 agentic CLI（能连续执行工具调用） |
| 轮数控制 | 人工判断 | 文件计数 + 延期审批 |
| 时间控制 | 无 | 墙钟截止 |
| 终止保险 | 人工判断 | 四道规则类硬闸 |
| 通用性 | 最广（任何工具） | 较广（agentic CLI） |

两者共用 Phase 1-4 的阶段划分和 synthesis 格式，只是驱动方式不同。

## N. 已知限制

| 限制 | 说明 |
|------|------|
| **Phase 1 禁读无技术保障** | 本约束依赖 agent 的指令遵循能力，无法技术强制。缓解措施：Phase 1 启动时两个 agent 应同时开始，避免一个先写完给另一个制造偷看机会 |
| **board.md / turn.txt 并发写入竞态** | 轮询机制天然错开，并发概率低，无锁设计。turn.txt 是单字符文件，原子性更好。若出现并发写入，以 board.md 为准，turn.txt 可被任意 agent 纠正。若 board.md 损坏，人工从 git history 恢复 |
